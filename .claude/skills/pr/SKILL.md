# プルリクエストを作る

補足: $ARGUMENTS

## 原則

コミットログが「1つの変更をなぜ入れたか」なら、PR は
**「一連の変更で何を解決したか、そしてなぜこのアプローチを選んだか」**を書く場所。

レビュアーが最初に知りたいのは差分ではなく、**解こうとしている問題**。
そこから読み始められる本文にする。

## 手順

### 1. 差分の全体像を掴む

```bash
git log main..HEAD --format='%h %s%n%b'
git diff main...HEAD --stat
```

コミットログの Why を読み、この一連の変更が何を解決したのかを組み立てる。

### 2. 本文を書く

```markdown
## 背景

<何が問題だったか。なぜこの作業が必要になったか>

## 変更内容

- <レビュアーが差分を追う手がかりになる粒度で>

## 設計判断

<複数の選択肢を比べた点があれば、選んだ理由と採用しなかった案>
<ADR を書いたならリンクする>

## 確認したこと

- [ ] `pnpm test` が緑
- [ ] `pnpm lint` が緑（層境界ルールを含む）
- [ ] `pnpm typecheck` が緑
- <目視で確認したことがあれば具体的に>

## レビューで見てほしい点

<自信がない箇所、判断が割れそうな箇所を明示する>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

- タイトルは日本語。何をしたかが1行で分かるもの
- **「変更内容」だけの PR にしない。** 差分を見れば分かることの再掲になる
- 「レビューで見てほしい点」を空にしない。無いなら「特になし」と書くのではなく、
  自分が一番不安な箇所を書く。必ず1つはあるはず

### 3. push して作成する

```bash
git push -u origin <branch>
gh pr create --title "<タイトル>" --body "<本文>"
```

**push と PR 作成は外向きの操作なので、実行前に user に本文を見せて確認を取る。**

## 例

```markdown
## 背景

家系図のレイアウト計算で、養子縁組と再婚があると世代が一意に決まらない。
同一人物が実親経由で3代目、養親経由で4代目になるケースが実在するため、
深さ優先探索では出力が非決定的になっていた。

## 変更内容

- 世代割当を差分制約系として定式化し、Bellman-Ford で解くよう変更
- 矛盾を負閉路として検出し、`diagnostics` に警告として積むように
- `generation_override` による手動解決に対応
- 叔父と姪の婚姻を含むフィクスチャを追加

## 設計判断

養子リンクを世代制約に含めていない。含めると実親経由と養親経由で矛盾する
ケースが頻発し、ほとんどの家系で警告が出て使い物にならなくなるため。
詳細は docs/adr/0002-generation-assignment.md

## 確認したこと

- [x] `pnpm test` が緑（layout-engine のテスト観点 1〜9 を全てカバー）
- [x] `pnpm lint` が緑
- [x] `pnpm typecheck` が緑

## レビューで見てほしい点

矛盾検出時に「婚姻制約を落として続行する」という復旧方針が妥当かどうか。
配偶者の高さがずれた家系図が出ることになるので、
いっそエラーにして描画しない方が良いという判断もありえます。

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```
