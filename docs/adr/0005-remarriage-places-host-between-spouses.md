# ADR-0005: 再婚ではホストを配偶者で挟んで配置する

- Status: Accepted
- Date: 2026-07-26

## 状況

[layout-engine.md](../design/layout-engine.md)「3. 横位置計算」は、配偶者をホストの
片側へ婚姻順に積む規則だった。サンプル家系を描き出したところ、
再婚のある家系で2つの線が重なることが分かった。

春彦・千代（初婚）・佳代（再婚）が `0, 1, 2` と一直線に並ぶ。

- 再婚の婚姻線が `(1, 0) - (1, 2)` となり、千代のノード `(1, 1)` を貫く。
  1本の線が3人を通しに結び、千代と佳代が婚姻しているようにも読める
- 初婚の基点が `0.5`、再婚の基点が `1.0` と隣り合う。
  兄弟バーはどちらも親の世代 + 0.5 に乗るため、`[0, 1]` と `[1, 2]` が
  端点を共有して1本の横線になる。初婚の子と再婚の子の区別が消える

どちらも「配偶者を片側に積む」配置と「バーを親の世代 + 0.5 に置く」規則の交点で起きる。

## 決定

**ホストに配偶者が2人以上付く場合、婚姻順に左から並べ、ホストを1人目と2人目のあいだに置く。**

配偶者が1人のときは従来どおり、ホストが `partner1` なら右、`partner2` なら左に付ける。

## 理由

婚姻線が隣どうしを結ぶ最短の線になるので、貫きようがない。
それぞれの子が自分の婚姻線の真下に来るため、基点も兄弟バーも自然に離れる。
規則を1つ変えるだけで2つの問題が同時に消え、結線パス生成には手を入れずに済む。

前妻・夫・後妻という並びは、戸籍をもとにした家系図で慣用でもある。
婚姻順が左から右に進むので、兄弟を `siblingOrder` 順に左から並べる規則とも向きが揃う。

## 採用しなかった案

**再婚側の線に高さのオフセットを与える**

再婚の婚姻線を下へ膨らませた3次ベジェにして初婚の配偶者のノードを避け、
兄弟バーを婚姻の回数だけ下げて重なりを解く案。配置を一切変えずに済み、
`partner1` が左という並びも保てる。3人以上の婚姻にも同じ規則で伸びる。

採らなかったのは、**幹が別の線と重なるため**。再婚の基点は婚姻線の中点、
つまり初婚の配偶者の真下に来る。そこから兄弟バーへ降ろす幹は、
初婚の子へ降りる線と同じ位置を通ってしまう。貫通を1つ消して重なりを1つ増やす取引になる。

幹を斜めにして自分の子の中心へ降ろせば避けられるが、
「幹は基点から真下へ降りる縦線」という規則を崩すことになる。
加えてオフセットには上下から挟まれた制約がある。初婚の配偶者のノードを避けるには大きく、
兄弟バーを子の段へ押し下げないためには小さくしたい。両立する幅は狭く、
婚姻の回数が増えるほど成り立たなくなる。結局こちらも3人以上には耐えない。

**配偶者を左右交互に積む**（1人目は規定の向き、2人目は反対側、3人目はその外側）

単婚の「`partner1` が左」を完全に保てる。
採らなかったのは、ホストが `partner1` のとき初婚が右・再婚が左になり、
婚姻順が右から左へ進むため。兄弟を左から並べる向きと逆行し、
子のグループも初婚が右・再婚が左になる。

## 影響

- 再婚のある家系では `partner1` / `partner2` の左右指定が効かない。
  [data-model.md](../design/data-model.md) は `partner1_id` / `partner2_id` を
  「左右の配置順を兼ねる」と定めているが、その保証は単婚に限られる
- **3人以上と婚姻した人物では貫通が残る。** 一列に並んだ4人の中央から
  3方向へ交差なく線を引くことはできない。解くには結局オフセットが要る。
  戸籍で3度以上の婚姻は稀であり、2度目までを正しく描くことを優先する
