# ADR-0009: 書体はブラウザ既定に任せる

- Status: Accepted
- Date: 2026-07-27
- Supersedes: [ADR-0008](0008-self-hosted-sliced-web-fonts.md)

## 状況

[ADR-0008](0008-self-hosted-sliced-web-fonts.md) で `@fontsource` の分割版を
自前配信する形にし、実装も入れた。動くところまで確認できている
（初回 8断片 89 KB、旧字体も網羅）。

そのうえで**やめる**ことにした。理由は技術的な失敗ではなく、
今の段階で払う必要のないコストだと判断したため。

Phase 2 はまだ最初の描画コンポーネント（`VerticalName`）にも入っていない。
書体の実体を持つことで既に付いてきていたものが、次のとおりある。

- `dist/` が 12 MB、うち書体が 11.6 MB。CSS バンドルも 272 KB（gzip 120 KB）で
  JS より大きい
- 依存が2つ、`@font-face` が247件。`fonts.css` と `fonts.test.ts` という
  維持するファイルが2つ
- Phase 5 の PNG / PDF 書き出しで、断片120個をどう埋め込むかという宿題

**書体が決まっていないと進められない作業は1つも無い。**
縦書きの `<tspan>` 配置も、結線も、レイアウトの検証も、書体に依存しない。

## 決定

**`@fontsource` の依存と `fonts.css` を外し、`--font-display` / `--font-body` は
汎用ファミリだけを指す。**

```css
--font-display: serif;      /* 人名（縦書き） */
--font-body:    sans-serif; /* UI・編集画面 */
```

トークンの名前（`display` / `body`）と用途はそのまま残す。
書体を差し替えたくなったとき、変えるのは `tokens.css` のこの2行だけになる。

## 理由

**和風の見た目は失われない。** 日本語環境の `serif` は明朝体に解決される
（macOS はヒラギノ明朝、Windows は游明朝）。人名が明朝で縦に並ぶという
このアプリの特徴は、既定の書体のままでも成立する。

**書体名を残して読み込まないことはしない。** `'Shippori Mincho', serif` と
書いたまま実体を読まない状態は、まさに ADR-0008 が問題として挙げたもの。
画面はフォールバックで普通に出るので、読み込まれていないことに気づけない。
加えて、閲覧者のマシンにその書体が入っているかどうかで見た目が変わり、
「誰が見ても同じ家系図」から遠ざかる。**指しているものと描かれるものを一致させる。**

**戻すのは簡単だという確認が済んでいる。** ADR-0008 の判断（CDN ではなく自前配信、
一括ではなく `unicode-range` 分割）は測ったうえでのもので、その内容はあの ADR に
残っている。必要になったら読み直して同じことをやればよく、
`fonts.css` は9行しかなかった。**判断を捨てるのではなく、適用を後ろにずらす。**

## 採用しなかった案

**トークンに書体名を残したまま `fonts.css` だけ外す**

後で読み込みを足すときに `tokens.css` を触らずに済む。採らなかったのは
上の「理由」の通りで、名前と実体が食い違う状態そのものを避けたいため。
`fonts.test.ts` はまさにその食い違いを捕まえるために書いたテストで、
これを残すなら読み込みも残すことになる。

**ADR-0008 を書き換えて「やめた」と追記する**

ファイルが1つで済む。採らなかったのは
[ADR の README](README.md) が「一度 Accepted にした ADR は書き換えない。
判断が変わったら新しい ADR を書き、古い方の Status を Superseded に変える」と
定めているため。**測って選んだ経緯が残っていること自体に価値がある。**
書体を入れ直すときに読むのは ADR-0008 で、そこに数字が無いと測り直しになる。

**日本語の Web フォントを1つだけ、人名用に読む**

`--font-body` を既定に落とし、人名の `--font-display` だけ Shippori Mincho を読む案。
配信量は半分になる。採らなかったのは、**半分でも 5〜6 MB は残る**うえに、
「なぜ人名だけ」という判断を別に説明しなければならなくなるため。
今やめる理由は量ではなく「まだ要らない」なので、中間を採る意味が薄い。

## 影響

- **`dist/` が 12 MB から 264 KB になる**（`pnpm build` で実測）。
  woff / woff2 は0個。CSS バンドルは 272 KB → 0.37 KB で、
  残っているのは実質トークンの `:root` だけ
- **見た目が閲覧者の OS に依存する。** ヒラギノ明朝と游明朝で字形が違うので、
  同じ家系図が環境ごとに少し違って見える。書体を固定したくなる一番の動機は
  たぶんこれになる
- **`fonts.test.ts` が無くなる。** トークンが名指す書体と `@font-face` の
  対応を突き合わせるものだったので、名指す書体が無くなると検証対象も無くなる。
  書体を入れ直すときは、あのテストから書き直す
- **`VerticalName` の字送りを既定の書体で詰めることになる。**
  後で書体を変えると詰め方の調整もやり直しになる。
  縦書きの字間・約物の見え方は書体で変わる
